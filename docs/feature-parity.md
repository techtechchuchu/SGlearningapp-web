## 이식된 계산·데이터 규칙

`backend/legacy.py`에는 Streamlit 화면과 시작 시 DB 쓰기 동작을 제외한 기존 함수 97개를 보존했다.
주요 규칙은 다음과 같다.

- X-패턴 학교별 offset 저장과 원래 문제번호 표시
- 문제번호 파싱·정렬·중복 제거
- 학생 명단의 복수 교재 분리
- 교사별 담당 학생 필터
- 월요일~일요일 주간 제출 집계
- 오답 Paper 제목·파일명·엑셀 열 생성
- 출력 대기 자동 등록과 완료 처리
- 학교 기출·채점결과 파일 중복 확인
- 학생 이름 변경 시 외래키 순서 보존
- 계정 간 오답 이전 시 중복 번호 제외
- 회원목록 복구 시 기존 계정 갱신

## 현재 안전 경계

현재 `/staff`는 UI·기능 흐름 검증용 체험 데이터만 사용한다. 운영 Supabase에는 읽기·쓰기하지 않는다.

운영 연결 전 다음 조건을 충족해야 한다.

1. 선생님·관리자 계정을 Supabase Auth 또는 별도 서버 인증으로 전환한다.
2. 브라우저에 `service_role`, 관리자 비밀번호, AI API 키를 넣지 않는다.
3. 담당 선생님은 자기 학생만 조회·변경하도록 서버에서 다시 검사한다.
4. 전체 관리자 작업은 감사 로그와 재확인 절차를 둔다.
5. 공개 역할에 `ALL ... USING (true)`로 열린 기존 RLS 정책을 먼저 축소한다.
6. 학생 명단 전체 교체, 이름 변경, 계정 이전은 트랜잭션으로 처리한다.
7. 별도 테스트 환경에서 Streamlit 결과와 웹 결과를 학생 수·문제 수·문제번호 단위로 비교한다.

이 안전 경계가 준비되지 않은 상태에서 운영 DB 연결을 활성화하지 않는다.
